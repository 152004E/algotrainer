# 05 — Terminar / verificar F2L

- **Prioridad:** Media
- **Estado:** pendiente

## Contexto

`src/data/f2lCases.ts` tiene **42 casos** poblados. Varias inconsistencias a
revisar:

- El catálogo (`algorithmCatalog.ts`) reporta **41** casos para F2L.
- No hay script que valide los casos F2L (solo OLL y WV tienen validación).
- El trainer F2L usa `useTrainer` con `currentCase.scramble` fijo (estático),
  que puede estar roto si `scramble === algorithm` en algunos casos (deuda
  conocida del dataset).

## Qué hay que hacer

- [ ] Auditar los 42 casos: `id`, `name`, `algorithm` correcto, `scramble`
      correcto (o regla: `invert(algorithm)`).
- [ ] Completar casos faltantes si el set real es mayor/otro (41 casos estándar
      de F2L "41 cases" + el resuelto).
- [ ] Script de verificación F2L:
      - scramble aplicado → estado = caso.
      - algoritmo aplicado → resuelve (desechando D capa ya resuelta).
      - parseo del alg sin pares redundantes.
- [ ] Sincronizar `count` del catálogo con el dataset real.
- [ ] Disponible en el trainer (consumir del catálogo → Tarea 1 de trainer).

## Criterios de aceptación

- [ ] Todos los casos F2L resuelven correctamente el scramble.
- [ ] Conteo catálogo == dataset == documentado.
- [ ] Script de verificación pasa.
